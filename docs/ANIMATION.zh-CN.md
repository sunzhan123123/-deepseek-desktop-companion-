# 状态、片段与消息同步

## 六种姿态

| 状态 | 画面含义 | 手机 / 平板 |
| --- | --- | --- |
| A | 桌前空手待机 | 手机在桌上；平板工作状态 |
| B | 桌前持手机阅读或打字 | 同一手机在左手；平板工作状态 |
| C | 桌前持手机，准备离座 | 手机在左手；平板关闭 |
| D | 坐在床沿 | 手机在左手 |
| E | 床上清醒，侧卧持手机 | 手机在左手 |
| F | 床上闭眼睡觉 | 手机熄屏放在床头小桌 |

首尾姿态图是 `room-animation-v2/pose-A.png` 至 `pose-F.png`，均为完整房间画面。当前素材实际分辨率为1916×1080，近似16:9；重做时不要把同一套素材混成不同尺寸或裁切。

```text
A ←→ B ←→ C ←→ D ←→ E ←→ F
     ↻阅读           ↻阅读  ↻睡眠
     ↻真实打字       ↻真实打字
```

程序沿最短路径逐段播放，不会直接从 A 瞬移到 F，也没有任意动作生成器。阅读和打字使用不同文件。A 的轻微呼吸由 `idle-breath-v4.js` 对静态图做本地形变，不需要 `loop-A.mp4`；C、D 是过渡落点，没有独立待机循环。

## 收到消息后发生什么

1. 服务接收消息并更新桌前/睡觉目标；无关键词时保持原目标。
2. 角色从当前落点沿路径到持机状态：桌前一侧在 B 读消息，床上一侧在 E 读消息。普通问题也会唤醒 F 中的角色去取手机。
3. 角色播放本轮真实手机打字片段；模型同时生成文字。若模型仍在处理，程序可继续新的完整打字周期。
4. **模型完成、并且本轮打字视频真实自然结束**两个条件都满足后，回复才显示。阅读循环不能替代打字结束。媒体暂停、丢失或控制房间断连时，回复可能继续等待。
5. 本轮完成后，角色按当时的目标回 A 或 F；新消息排队处理。目标和“画面已经到达的姿态”是不同信息。

手机视频是预先生成的表演，不会逐字对应模型输出，也不意味着模型真的在控制手机系统。聊天内容在独立窗口显示，不会被绘制进视频手机屏幕。

## 关键词的真实规则

当前实现按文本从左向右扫描 `/起床|床|睡|桌|上班|加班|工作/`，最后一次命中的结果决定目标。`起床` 在同一位置优先匹配成完整词，因此不会再把其中的“床”单独判为睡觉。

| 消息示例 | 最后命中 | 目标 |
| --- | --- | --- |
| `去睡觉` | 睡 | F |
| `起床` | 起床 | A |
| `睡醒去工作` | 工作 | A |
| `工作完上床` | 床 | F |
| `不要睡` | 睡 | F |
| `请解释“睡”这个字` | 睡 | F |
| `你好` | 无 | 保持原目标 |

规则不分析否定、引号、条件句或模型回答。改人设提示词不会改变这段路由代码。若要增加动作或语义理解，需要修改服务端规则、前端状态图和素材，并相应验证。

## 连续性与原型限制

图生视频可能在眼睛、手指、手机方向、衣服、床被、人物比例和亮度上漂移。当前已有片段和调色修正，不代表全部接点逐像素一致；尤其离/入座、床沿与被窝、放取手机和循环重播处，要以实际播放检查。

程序尽量等当前片段自然结束后切换，并预载下一片段；这些措施能减少播放器切换闪烁，无法补出缺失的手部动作或修复生成内容本身的跳变。新素材需单独检查“上一段最后一帧 → 姿态图 → 下一段第一帧”，不要只检查每段单独看是否好看。

本项目没有加入版权歌曲。视频在房间页面静音播放；自定义配乐如需再分发，应先取得相应授权。素材使用与再分发还须遵守 [素材说明](../ASSET-NOTICE.md)。
