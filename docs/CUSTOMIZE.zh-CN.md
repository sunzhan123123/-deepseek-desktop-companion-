# 换成自己的角色

[返回首页](../README.md) · [姿态图提示词](../prompts/KEYFRAME-PROMPTS.zh-CN.md) · [动画提示词](../prompts/ANIMATION-PROMPTS.zh-CN.md)

最省事的改法是保留六种姿态、原有构图和文件名，把角色换成你有权使用的角色。换房间布局、移动桌床或增加动作，则需要同时改画面、程序和测试。请在复制出的项目中操作，并保留原媒体备份。

## 1. 先准备六张完整姿态图

使用自己的角色参考图，先完成一张稳定的“房间＋角色”主图，再由同一主图编辑出 A—F。生成工具和模型由你选择，提示词入口见 [六姿态图稿](../prompts/KEYFRAME-PROMPTS.zh-CN.md)。本项目不附原角色的训练图、私人参考图或生成账号。

| 姿态 | 必须可见的事实 |
| --- | --- |
| A | 角色在桌前空手；手机在桌面固定位置 |
| B | 左手持同一手机阅读；另一只手在桌面；平板工作状态 |
| C | 保持 B 的构图与握机，只有平板关闭及局部光随之改变 |
| D | 同一角色坐在后方床沿，左手仍持手机 |
| E | 沿床侧卧，左手持手机，另一只手托头，腿在被下 |
| F | 保持卧姿并闭眼，双手不持手机；手机熄屏放在床头小桌 |

输出为完整不透明 PNG，统一尺寸和裁切，命名为 `room-animation-v2/pose-A.png` 至 `pose-F.png`。当前发布素材为1916×1080；保留这个画布和桌床位置，可减少播放器之外的坐标适配工作。角色离开书桌后，椅子、桌面、床头和家具都需要正确露出，不能用拉伸前景遮住缺失背景。

建议先做一张没有角色的干净房间底图，固定家具和灯光，再编辑角色；底图是制作辅助，不是必须新增的运行文件。A—F 的墙面、窗帘、桌床、椅子和台灯应来自同一套布局，避免六次文生图把整个房间重画六遍。

## 2. 制作15段视频

按 [动画提示词](../prompts/ANIMATION-PROMPTS.zh-CN.md) 的首尾帧表，分别生成10段方向动作、3段循环和2段手机打字。不要把 B 的阅读循环改名当成打字，不能只拍手握手机摇动。B/E 打字都要有手指在朝向角色的屏幕一侧真实点按，结束时恢复原姿态。

现有程序按视频真实时长等待结束，不强制所有素材都是5秒。建议动作在5—10秒内自然完成，保留短暂停稳，导出兼容浏览器的 MP4，例如 H.264、`yuv420p`。画幅、裁切和色彩应与姿态图保持一致。生成模型可能忽略时长/动作要求，仍需实片验收。

文件名必须保持：

```text
room-animation-v2/
  AB.mp4 BA.mp4 BC.mp4 CB.mp4 CD.mp4 DC.mp4
  DE.mp4 ED.mp4 EF.mp4 FE.mp4
  loop-B.mp4 loop-E.mp4 loop-F.mp4
companion-typing-v1/
  B.mp4 E.mp4
```

## 3. 处理当前画面专用代码

这版含两项按原画面坐标编写的本地处理，不能默认适配任意新角色：

- `idle-breath-v4.js`：A 的呼吸区域、轮廓、固定边界和形变中心。角色位置、头发轮廓、比例改变后需重画 `REGION`、`OUTLINE` 等范围，避免桌子或头饰跟着变形。
- `room-mark-cover-v4.js`：右下角地板的固定区域修补。新图没有相同区域时，应按新画面重做或移除这项处理。**仅删除脚本标签会令房间初始化失败**：`room-companion-v1.html` 同时依赖它的 `ready`，且通过 `data-mark-ready` 控制画面可见；需一起调整初始化和可见性逻辑，再检查视频切换。

对第一次改图的用户，建议先保持构图，只替换角色，再由懂 JavaScript 的人检查这两处。无需改动独立聊天窗口来完成角色视觉替换。

## 4. 修改聊天人设

默认人设在 `deepseek-companion-runtime-v1.mjs` 的 `deploymentPatch()` → `system-prompt` → `personaPrefix`。当前内容是小鲸/大肥鱼、称用户为“主人”、默认1—2句短回复。你可以修改名字、称呼和语气，保存后完整停止并重新启动程序。

建议保留事实约束：不虚构已经完成的动画；目标与实际姿态分开；需要当前时间时读取工具并说明读取时刻；不声称可控制真实电脑。时间快照位于 `companion-live-context-v1.mjs`，不建议用写死的日期替换它。

修改源码人设不等于清除已有会话记忆。聊天框“清空聊天记录”也只清可见记录；验证新角色时应使用隔离的新数据目录，避免旧会话影响判断。不要把个人数据目录或凭据一并复制进自定义发布包。

## 5. 如果要加新动作

现有运行时只认识 A—F 和 B/E 打字。增加“喝水”“挥手”等动作，至少需要共同更新：

| 部分 | 需要检查的内容 |
| --- | --- |
| `room-companion-v1.html` | `graph`、`loops`、标签、预载、静态姿态与转场 |
| `deepseek-companion-server-v1.mjs` | 关键词/目标决策、持机落点、每轮状态与媒体要求 |
| `companion-room-v1.js` | 房间连接、打字周期及自然结束确认 |
| `companion-live-context-v1.mjs` | 给模型的真实位置和动作描述 |
| 媒体、清单、检查脚本与测试 | 新文件、连接、完整性与消息同步 |

写提示词或改角色介绍不会自动扩展这些能力。先画状态图，再补真实衔接片段，最后验证旧路径与打字条件仍然成立。

## 6. 自定义后的验收

1. 在一个复制出的项目中替换素材，逐个检查文件能解码、尺寸一致。
2. 看 `AB→B阅读→B打字→BA`，以及 `BC→CD→DE→E阅读→E打字→EF→F睡眠`。
3. 再反向看 `FE→ED→DC→CB→BA`；检查唯一手机、左右手、椅子、床沿、被子和光照。
4. 发普通问题、睡觉、起床消息，确认文字等真实打字自然结束；使房间暂停再恢复，检查不会提前泄出回复。
5. 运行项目检查和测试。原 `assets/media-manifest.json` 的哈希描述的是发布素材，更换后会不匹配；先确认新文件，再按发布脚本的清单规则重新生成，保留你自己的素材许可说明。不要仅为通过校验而忽略差异。

生成文本清楚不代表成片已合格。每次修订记录“哪个接点、看到了什么、改哪个提示词/首尾帧、重做后结果”，比一次重生成全部片段更容易收敛。
